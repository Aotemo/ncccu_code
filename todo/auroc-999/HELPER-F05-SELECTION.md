# F05 最终选员 CPU 准备

范围仅为 `tools/diagnostics/f05_final_selection.py`、`tests/test_f05_final_selection.py` 和本说明。复用 F03 的完整同 population 轮次发现与公开源门、F04 的独立进程严格构造/完整推理状态导出与实际文件 SHA/字节、固定体积贪心和内部 dev z 等权函数；三汤沿既有 `f05_soup_dev.py` 检查实际父源、单独加载及已完成的八 rank 全 dev 分片。此处不派 GPU、不读官方，样本级预测不进入 Git。

在全部授权方向终态及任何新的 F05 融合结果读取前，由 owner 从 F03 发现结果和三汤／新模型补充清单建立完整候选，按事前固定顺序封存。当前候选与最终规则尚未封存；下面的 policy 格式只是可测试的接线草案，不宣称已有正式 F05 清单。清洗/蒸馏候选在其真实完成后才来自同一轮次发现，非完整或缺 selected 的条目列为 unknown。R256 在 F04 的历史排除仍保留；它已获准作为 F05 汤父模型，能否作为 F05 独立候选以未来完整封存规则为准，不在此猜测。

`screen_candidates` 对每个达到单模 `AUROC >= 0.988` 的轮次使用 `f04_export_member.py` 的实际严格构造/重载回执，并重新核 checkpoint、sidecar、freeze、science、两精度文件 SHA/实际字节及 online/EMA 身份。已有导出若绑定较早库存，须实读旧库存并按 F04 `require_same_candidate` 核该成员与现库存所有身份完全相同，不能把旧库存 SHA 写作新库存 SHA。历史任务内 fit 适配成员还须绑定现有适配审计与该轮真实阶段回执；证据缺失列 unknown。每个均匀汤使用原真实父模型 SCIENCE、来源、已有 strict standalone/export，以及完整内部 dev producer 输入和 rank packet；未完成／缺文件／来源不明列 unknown，低于门槛列排除；N06/FLAIR 不准入。未解决的 unknown 会阻止当前 helper 函数生成最终预封存，不能静默跳过并把剩余集合声称完整。

`freeze_selection` 接受外部真实封存的 `f05-final-selection-policy-v1`：绑定完整候选顺序、F03 inventory 和 soup catalog 两项 SHA、全部授权方向的终态小回执、`.988` 门、单模 AUROC 降序/同分按封存顺序、`500000000` 实际 fp16 字节、遇到下一成员超限立即停止、内部 dev float64 总体标准差 z 等权、`TTA=false`、`official_read=false` 和未读新融合。该 policy 结构须经 08ac 审阅并与正式终态回执约定后才能用于正式选择；不是根据现有结果预先产生的最终合同。当前汤验真适配已登记的三组均匀汤；若次方案贪心汤或其他新汤真实存在，须先补充其来源与验真适配，未知项不得静默遗漏。

命令行只做候选筛查和预封存：显式输入 SHA 固定的 `--inventory`、`--soup-catalog`、`--policy`、`--evidence`、当前 Pod 完整树 `--source-proof`、`--remote-metadata`、`--git-commit`、`--work-root`、新 `--output`；缺失项保留 `SCREEN.json` 并拒绝生成 `PREFLIGHT.json`。它不运行 GPU 或最终融合。现有 F04 全 dev 的原 fp16 分片未逐文件 SHA 绑定，不能将其事后散片冒充已封存的最终预测。正式融合须在选员预封存 SHA 后，由唯一 GPU owner 使用现有监督链取得每个选中成员固定 fp16 存储的完整内部 dev 单视图分片，核 checkpoint/导出、成员、顺序、行与 rank proof，再复用 `fuse_internal_dev` 的 F04 z 等权与 AUROC/AP。此函数是纯数学核，调用方必须先独立验证分片血缘；最终 producer 的预测封存和调用入口尚需 08ac 接线，不能把纯函数合成结果当正式 F05 dev 指标。官方评估仍只有最终冻结后的独立 F05 一次 claim。

候选补充文件草案为 `{format:'f05-soup-candidates-v1', official_read:false, soups:[{id:'soup-r120'}, {id:'soup-r134r1'}, {id:'soup-r201'}]}`；未来若增加其他已完成汤，须在其 adapter 和来源核验完成后、政策封存前扩充。私有证据文件 `{format:'f05-candidate-evidence-v1', official_read:false, entries:{...}}` 按候选 ID 指向轮次 F04 `EXPORT.json` 的 `{path,sha256}` 或汤的 `{inputs:{path,sha256},summary:{path,sha256}}`；轮次如果复用旧库存导出，改为 `{export:{path,sha256},original_inventory:{path,sha256}}`，如涉及 fit 适配再提供 `adaptation_audit` 与 `adaptation_receipt`。各路径由真实证据确定，不将占位 ID 或虚构 SHA 作为正式输入。

policy `direction_terminals` 必须恰含 `soup`、`oof`、`clean`、`distill`、`resolution_768` 五个 `{path,sha256}`；每项的真实终态汇总须标明对应 `direction`、`status` 为 `completed` 或 `closed_no_candidate`、`official_read=false`。这一结构只是接口提案，须与该时实际终态/归档回执协调；任一方向 unknown 时不能编造终态或冻结。实现的 `fuse_internal_dev` 是无 I/O 数学函数，调用前 owner 必须按最终 policy 独立核验内部 dev 分片，不能用包含官方预测的输入。
