# F05 空闲 CPU 借用与 P3 并行合同

目的：在唯一 GPU owner 已确认某 Pod 安全空闲时，让 CPU 准备任务使用该 Pod 的全部实时有效 CPU；GPU 接续前恢复 80/20 并核互斥。现有 P3 旧扫描只能完成当前原子分段后停下，新旧扫描器绝不并发写同一目录；保留其原输入、分段和回执。当前旧循环控制已停止，最后分段写至 24830/51396，须经新扫描器连续性检查确认。

最小文件范围拟为 `configs/RESOURCE-POLICY-IDLE-CPU.json`、`tools/environment/cpu_budget.py`、`tools/environment/pod_cpu.sh`、对应 CPU 预算/通道测试、`tools/diagnostics/p3_hard_case.py` 和 P3 窄测试；必要的 GPU 准入互斥核查仅限现有 `runtime/bundle/retrain/site_binding.py` / activation 入口，不新建调度服务。老资源 policy、allocation、训练包和历史回执不改写。策略通过版本化配置及 env 明示：常规训练/准备仍为 `4/5` 与 `1/5`，空闲模式 CPU 为 `1/1` 且不可用于 GPU 训练准入。

借用须先逐 Pod 实时核 UID/Ready、有效 affinity/cpuset/quota、前轮 owner/rank 安全终态、设备句柄和卡空闲，记录绑定与短时效安全证明；任何权限不足、设备用户或身份不符为 unknown，不借用。生成独立 CPU allocation，并以已有 nice19/隐藏 CUDA/HIP/ROCR 的任务树监督回执记录实际 mask、峰值 runnable 与利用情况。借用期间 GPU 不启动；要启动前停止借用任务、确认其进程树退出、重建/校验常规 80/20 不重叠 allocation，再走原 GPU owner/设备门。空闲另一 Pod 可独立借用；不热改活跃任务。

P3 使用冻结输入、原顺序、相同 hash/质量定义和原子分段。新扫描并发度由当次 CPU allocation 决定，每个计算 worker 单线程；初始最多 16，保留父进程一核，最高不超过 allocation−1。以每批最多 64 张的缓存读取耗时 p95 及本扫描器 worker 的 D 状态比例反馈：p95 >2 s 或 D 比例 ≥25% 则下一批并发减半（至少 1）；p95 <0.25 s 且 D <10% 连续两批则增加 8，至 allocation−1 为止；p95 >5 s 或 D ≥50% 则暂停 30 s 后重测，持续异常保留 unknown/失败并如实汇报。无固定 4 图/s 上限；不得为提高利用率加重已见 NFS 故障。每批结果按原顺序组装，成功完成的连续片段原子写入；样本级数据仍只留 exp-v3。

实现细则：阈值取本批缓存或校验原图读取时间的 p95 与只读采样的本扫描器线程 D 状态峰值；执行期间一旦观察到 D ≥50%，不再提交该批新的行，已在途行安全完成后按连续顺序封存并暂停。连续三批触发暂停则停止并记录余项 unknown；新扫描器只在旧扫描进程已退出后取得独立互斥锁，重新核原始封存源码 SHA、输入及既有片段连续性。原扫描源码和原始 INPUTS 回执保留不覆盖。

验收：合成 CPU/quota/身份/时间/借用证明及重叠反例、旧 80/20 回归、P3 并发结果与串行等价/失败停机和限速回归必须在 Pod CPU 通过；新代码提交、push、精确部署后，以两 Pod 真实有效核/设备身份与任务树回执报告可用、分配、实际峰值 runnable，不能把分配核数当成实际利用率。P3 同口径完整汇总与 167 正例对 fit 负例的反标签双 hash 对照完成后归档，不读官方、不回灌训练或选模。
