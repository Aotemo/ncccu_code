# F05 模型汤：事前合同

目的：只使用合规公开预训练及本任务 fit 训练得到、实际可严格加载的 selected 权重，测试同配方不同 seed 的参数均匀平均。禁止医学来源、N06、官方数据和 TTA。先封存三族完整身份/加载清单及原单模 dev 指标，再读取任何新汤的 dev 结果；缺失、不同预训练源、配置不兼容或权重不匹配的成员单列并排除，不能虚构补齐。

固定候选顺序：

1. R120 系：R120、R254、R256、R258、R262。
2. R134R1 系：R134R1、R253、R257、R260、R261。
3. R201 系：R250、R252、R259。

每族按其真实原始 SCIENCE、公开权重 revision/SHA、数据划分、模型构造、推理配置及 selected variant/张量摘要核兼容；允许预先列出的 seed 与该轮独立身份不同，不因结果调整。R256 在 F04 依事前 P2 排除；用户现明确允许其作为 F05 的汤成员，不更改 F04 历史记录。至少两个兼容可加载成员才构成汤。

主方案是每族全部准入成员的参数及浮点 buffer、head、age、BN 等权算术均值；键、shape、dtype 不一致即拒绝，非浮点 buffer 必须所有成员相同才原样保留。用严格模型构造和独立小型合成输入先检验，保存可追溯初始 selected SHA、完整参数 SHA 与 fp16 实际字节；原始 selected 永久保护。

次方案按原单模内部 dev AUROC 降序（相同按上述候选顺序）从最佳单模开始，依次尝试等权加入下一成员；只有完整 dev AUROC 不低于已保留汤才加入，平分正确对用既有精确 `error_twice` 比较，不按 AP 或其他错例增删。逐次读取同一 dev 属自适应选择，须与无贪心选择的主方案分列并明确偏差。若单模或完整 dev 评估缺失，记录 unknown/失败，不自动替代。

每个主汤与每次次方案尝试复用既有严格加载、八设备监督和内部 dev 评估入口；每图固定单视图一次，无官方读取。按现有身份、设备、20 GiB 容量及 80/20 互斥门，先 CPU 测试、提交 push 和精确部署；任一 Pod 安全终态即可安排，不因审计或文档等待。F05 最终融合候选与选择门须在读取任何新的 F05 融合结果前另行封存；该汤合同不授权直接选最终融合或官方评估。

拟最小影响 `configs/F05-MODEL-SOUPS.json`、`tools/diagnostics/f05_model_soup.py`、对应测试，以及为通用汤模型复用既有 GPU dev 监督所必需的 `tools/diagnostics/f04_gpu_full_dev.py` / 窄测试；不复制训练平台，不改 F04 冻结快照。先盘点来源与权重，再决定具体必要函数；以上文件范围若需扩展先登记理由。
