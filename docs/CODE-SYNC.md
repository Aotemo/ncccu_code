# 源码同步与部署

统一远端为 `https://github.com/Aotemo/ncccu_code`，本地目录为工作区内的 `ncccu_code/`。原工作区包含数 GB 混合历史，保留原位；本仓库从远端原有 README 提交接续，导入当前实验的必要源码。

每次后续实验：

1. 在 `runtime/` 与 `tools/` 修改唯一源码，在 Git 中检查差异。只改科学合同允许的部分。
2. 通过 Git 或已连接的 GitHub 工具提交到远端；确认远端分支指向实际 commit。没有推送回执不能写“已同步”。
3. 执行 A 在指定 Pod 核对 commit 对应文件的实际 SHA，生成部署清单。绝对路径与 token 由当次正式绑定产生，不能从本地路径推断。
4. 对受影响内容执行必要窄检查；不重复已经通过且未改变的模型/数据套件。配置解析和 SHA 验证均在 Pod。
5. 用同一独占 GPU owner 串行运行，保持固定数据、官方隔离和真实退出回执。运行记录保存 commit、逐文件 SHA、配置和唯一 checkpoint 身份。
6. 结果只同步汇总和小型必要回执。数据/模型在服务器按保留规则管理。

原训练入口会生成 `outputs/<run>/code/` 与 `source-files.json`。它们是模型绑定的运行源码快照，保留其原 bytes；后续维护以本仓库为准。为减少目录重复，后续实验不另维护完整开发包；需要冻结部署时从已同步 commit 导出，不能在独立副本中长期修改后忘记同步。

当前 R91/R92 迁入仓库不会改变运行源码、配置、clock 或 token。仓库 commit 是迁入版本的来源记录，不追溯声称历史训练当时已经绑定此 commit；历史真实身份仍以服务器 source digest/部署清单为准。
